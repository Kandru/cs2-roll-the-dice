# Roll The Dice HUD (AI)

C# under [`src/Hud/`](../src/Hud/): [`CustomHud.cs`](../src/Hud/CustomHud.cs) (spawn, transmit, `SetText` / `SetHasClass`, fade `ph-fading` → `ph-off`), [`Banner.cs`](../src/Hud/Banner.cs), [`HudTheme.cs`](../src/Hud/HudTheme.cs) (config `panorama_theme` → one `theme-*` on the card). One stylesheet: [`hud.vcss`](content/panorama/styles/custom_game/rollthedice/hud.vcss) (see [panorama-css.md](panorama-css.md)). Banner copy comes only from C# `IStringLocalizer` into `{s:dice}` — no hardcoded Label text in XML.

`workshop/content` is the addon root (copy into `csgo_addons/<addon>/`). Layouts load as `panorama/layout/custom_game/rollthedice/<name>.vxml_c`.

## Panorama versions

Repo sources stay `banner.xml`, `hud.vcss`.

## Server can only

1. Dialog var on the layout root card → Label text (never path/colour).
2. `SetHasClass` on a panel **id**.

No panel create / width / colour / image from C#. Layout edits need VPK republish.

**Round / notify:** `Banner.Notify` (center + panorama) and `Banner.Show` (panorama status); config `notify_player_via_centermsg` / `notify_player_via_panorama` via `BindConfig`. `Suspend()` clears owner/shown text + `CustomHud.ResetRound` (round start/end, intermission). `Shutdown()` clears state only (map end/unload). Never Kill/respawn live layouts mid-round.

**Spectator mirror:** per-owner text (incl. bots; only humans get `Present`). Resolve watch target by `ObserverTarget` handle → `PlayerPawn` (`ObserverPawn` then `PlayerPawn`). Alive non-observers see their own text. `OnTick` + `Show` sync. Death forces `Banner.Hide`.

**Fade:** show = `ph-fading` then clear next frame; hide = `ph-fading` 1s then `ph-off`.

## Layouts

| Layout | Root | Routed ids |
| --- | --- | --- |
| `banner.xml` | `Banner` | `Banner` (`{s:dice}`) |
| `banner.xml` | `Reel` | `Reel` (`{s:rr_title}`, `{s:rr_source}`, `{s:rr_win}`, global `{s:rr_credit}` / `{s:rr_hint}`), `ReelRow<n>` (global `{s:rr_f<n>}`, `tone-*`) |
| `info_v5.xml` | `ri-root` | every `ri-*` id; contract in [`InfoMenuIds.cs`](../src/Hud/InfoMenuIds.cs) |

`make panorama` validates ids/`{s:…}` against C#.

**Reel** ([`Reel.cs`](../src/Hud/Reel.cs)): slot-machine roll animation, visual only. Banner and reel share one layout entity; [`CustomHud`](../src/Hud/CustomHud.cs) tracks visibility per panel. The winner always sits in row 20, so one keyframe distance serves every roll; `replay-0/1` select the identical keyframes `rr-spin-a/-b`, because a re-added class with the same `animation-name` does not restart. Each roll clears `replay-*` on open and `ReplayGapSeconds` later sets the one the viewer did **not** use last (`Reel._lastReplay`). That memory survives `WriteDefaults`: after a round restart the client rebuilds the panel from XML, but the strip still remembers the animation it played last, so starting every round with `replay-0` left the first roll of each round frozen on the result. The tick sounds start with the spin, and the strip's resting transform under `replay-*` is the end position, so the winner stays even if `animation-fill-mode` is ignored. The strip has an explicit height (`RowCount * 44px`): `fit-children` inside the 132px window is capped and the lower rows would never be laid out (validated). No negative margins: ▼ and the left arrow are `rotateZ(180deg)` flips. Filler rows are global (written once per round), the winner row and all root classes are per viewer. Rows and theme rules are generated by `tools/gen_reel_panorama.py` (`make panorama` fails when they are stale). While a reel spins, `Banner.Notify`/`Show`, the player chat line and the dice sound are held back by `Reel.TryDefer*` and released on stop.

The reel footer shows the info command (`rr_hint`, left) beside the credit (right); both are global and written with the filler. Title, source and winner row follow the viewer's language (`Reel.TextsFor`, cached per culture); the filler strip is global and stays in the server language.

**Info menu** ([`InfoMenu.cs`](../src/Hud/InfoMenu.cs), data in [`InfoMenuSource.cs`](../src/InfoMenuSource.cs)): `!dice info` toggles a modal, mouse-driven menu on its **own** layout entity `info_v5.xml` (`info_v4.xml` stays in the addon for older plugin versions) (one layout per visibility group), driven by the ruleset's generic [`HudLayout`](../src/Hud/HudLayout.cs) (diff caches seeded with the XML defaults, `is-off` / `is-fading` on the root, own transmit filter, `Writes` counter). Open runs one timer after the command, input capture one timer after the first paint; the entity is pre-warmed 1s after map start. Rail tabs `ri-tab-0…5` = round (start page on every open), history, perks, commands, settings, admin (exclusive `is-active`; the admin tab is authored `is-off` and shown per player with `@rollthedice/admin`); root group `view-round` / `view-list` / `view-perks` / `view-settings` / `view-admin`. The round view shows CT and T side by side, each column its own scrolled pool of 32 rows `ri-ctr-N` / `ri-tr-N` (`is-off`, `tone-*`, `life-alive|dead`, `is-self`) with a team head (`ri_ct_h`/`ri_ct_n`, `ri_t_h`/`ri_t_n`). Every list is **one client-scrolled page** (`RiList`, `overflow: squish scroll`) over a pool of 112 single-line rows `ri-row-N` (`is-off`, `tone-none|good|bad|neutral|very-good|very-bad`, `team-none|ct|t`, `life-alive|dead`, `is-self`); the server never reads or sets the scroll position. A paint writes at most `RowWriteBudget` row changes and stays dirty, so a full list arrives over a few ticks instead of one burst; `ResetRound` restores the XML defaults the same way (`RestoreWriteBudget` per tick). Perks: category filter chips `ri-flt-0…5` (all, very good … very bad) (counts in the label), sort chip `ri-sort` (A-Z / type), search through the chat (`!dice info <text>`, Panorama has no server-readable text input) shown in `ri-search` with the clear button `ri-search-clear`. Round list: split into the CT and T columns (players without a team are left out), alive before dead; dead rows get a red frame and grey text (`life-dead`, no status label); the team is the index badge (wrapped in non-breaking spaces - a dialog variable that equals a client token such as `CT` gets localized). Settings: switch `ri-auto` (`is-on`, `is-disabled`), language buttons `ri-lang-0/1` (`is-active`) set the CounterStrikeSharp player language and save it in `player_configs`. Admin (data and actions in [`AdminMenuSource.cs`](../src/AdminMenuSource.cs), config section `admin`): global lock switch `ri-alock` (`is-on` = locked), section chips `ri-asec-0/1` with root group `asec-players` / `asec-perks`; player rows `ri-ap-N` (`is-on` = locked, `tone-*`, `team-*`, `life-*`) with the buttons `ri-apr-N` (random roll), `ri-apg-N` (pick a perk) and `ri-apl-N` (lock; two labels switched by `is-on`); perk rows are buttons `ri-ak-N` (`is-on` = may be rolled, `cat-off`) that toggle the perk or, while `ri-aperks` is `is-open`, give it to the picked player; category switches `ri-acat-0…4` (`is-on`). Button and state words are shared root variables (`ri_ab_*`), so a row costs only its own texts. Every admin click and every paint checks the permission again. Texts per viewer through `Localization.ForPlayerSafe` (CounterStrikeSharp's `ForPlayer` throws for bots). Closes on the close button, the command, death and round start. The whole layout and its theme rules are generated by `tools/gen_info_panorama.py` - change the generator, not the XML; bump `_vN` on contract changes (a running client keeps a loaded layout/stylesheet until restart). Literal label text is allowed only for `//`, `‹`, `›` (validated).
